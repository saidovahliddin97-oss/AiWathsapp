# WhatsApp Family Assistant

Бот, который пишет вашим родственникам в WhatsApp на естественном таджикском:
сам отправляет приветствия и, если включить, ведёт переписку так, как написали бы вы.
Главный принцип: звучать как член семьи и **никогда не выдумывать факты о вас**.

Полное техническое задание: [`CLAUDE_WHATSAPP_PROJECT_BRIEF.md`](CLAUDE_WHATSAPP_PROJECT_BRIEF.md).

## 🚀 Бесплатный запуск на Mac (5 шагов)

**Что понадобится:** MacBook, WhatsApp на телефоне, 15 минут.
Модель — бесплатные модели через OpenRouter (Gemma, Qwen и др., работает и из России).
WhatsApp подключается бесплатно, как «WhatsApp Web». Бот отвечает на языке собеседника:
по‑таджикски на таджикский, по‑русски на русский.

1. **Скачайте проект.** На GitHub, в ветке этого проекта: зелёная кнопка **Code → Download ZIP**,
   распакуйте папку (например, на Рабочий стол).
2. **Установите две программы** (один раз, бесплатно):
   - Python 3.12 — https://www.python.org/downloads/macos/ (кнопка Download → установить);
   - Node.js LTS — https://nodejs.org/ (левая кнопка → установить).
3. **Запустите `start.command`**: правый клик по файлу → «Открыть» → «Открыть»
   (или в Терминале: `bash ~/Desktop/<папка>/start.command`).
   Скрипт сам:
   - откроет openrouter.ai → войдите (можно через Google), **Create API Key**,
     скопируйте ключ и вставьте его прямо в окно Терминала (карта не нужна);
   - спросит ваше имя (для общих групп);
   - откроет `config/relatives.json` → впишите родственников (номер без +, имя,
     как вы к ним обращаетесь, `elder`/`peer`/`younger`), сохраните, Enter.
4. **Отсканируйте QR‑код**, который появится в окне: на телефоне WhatsApp →
   Настройки → **Связанные устройства** → Привязка устройства.
5. Готово: в окне появится «✅ WhatsApp подключён». **Не закрывайте окно** и не
   закрывайте крышку ноутбука — бот работает, пока окно открыто. В следующий
   раз достаточно снова запустить `start.command` (QR больше не нужен).

### Чей номер использовать — `PERSONAL_NUMBER`

| | `PERSONAL_NUMBER=true` — ваш личный WhatsApp | `PERSONAL_NUMBER=false` — отдельный номер (2‑я SIM) |
|---|---|---|
| Родственникам | ничего не меняется | нужно сказать про новый номер |
| Если вы ответили сами | бот замолкает в этом чате на 2 часа | — |
| Уведомления и команды | в чате «Вы (Избранное)» | на ваш личный номер (`OWNER_PHONE`) |
| Риск блокировки | небольшой, но под угрозой **ваш** номер | под угрозой только номер бота; новый номер лучше сначала 1–2 недели использовать вручную |

Подключение через «Связанные устройства» — неофициальное (библиотека Baileys) и
формально нарушает правила WhatsApp. Бот ведёт себя как человек («печатает…»,
паузы, не больше `BRIDGE_MAX_PER_HOUR` сообщений в час, приветствия с паузами
1–5 минут), но риск полностью не исключён.

### Управление прямо из WhatsApp

Пишите команды себе в «Избранное» (личный номер) или со своего телефона боту (2‑я SIM):

| Команда | Что делает |
|---|---|
| `/блок Али` · `/блок 992901234567` · `/разблок …` · `/блоклист` | бот никогда не отвечает этому человеку |
| `/всем вкл` / `/всем выкл` | отвечать всем в личных чатах / только людям из списка |
| `/добавить 992901234567 мама Модарҷон` | добавить контакт (кто: мама, папа, брат, сестра, ака, апа, хола, тағо, друг…) |
| `/удалить Модарҷон` | убрать контакт |
| `/авто вкл Модар` / `/авто выкл Модар` | с этим человеком бот переписывается / только приветствия |
| `/авто вкл` / `/авто выкл` | то же сразу для всех |
| `/группы` · `/группа вкл Оила` | список групп · разрешить отвечать в группе (по умолчанию все группы выключены) |
| `/привет Модар` · `/привет всем` | отправить приветствие сейчас (всем — с паузами) |
| `/рассылка вкл` / `выкл` | приветствия по расписанию |
| `/пауза 3` · `/старт` | бот молчит 3 часа · снять паузу |
| `/почему` | что бот сделал с последними сообщениями и почему (не ответил / ответил) |
| `/статус` · `/список` · `/помощь` | состояние, контакты, список команд |

### Что бот делает сам
- **Отвечает всем в личных чатах** (кроме `/блок` и бизнес‑аккаунтов). О каждом новом
  собеседнике присылает вам одно уведомление с готовой командой `/блок`. С людьми не из
  списка говорит вежливо и нейтрально, не придумывая родства. Приветствия по расписанию
  получают только люди из списка.
- **Приветствия по расписанию**: тем, с кем не было переписки `GREETING_INTERVAL_DAYS`
  (7) дней, с 10 до 20 часов, по 1–3 человека за раз, с паузами. Сразу после
  установки никому не пишет — отсчёт идёт с первого запуска.
- **Режим GREETING_ONLY** (галочка выключена): только приветствия; ответы
  родственников пересылаются вам.
- **Режим FULL_CHAT** (галочка включена): отвечает на сообщения как вы.
- **Группы**: по умолчанию бот их полностью игнорирует. После `/группа вкл <название>`
  отвечает в этой группе, только если к вам обращаются по имени (`OWNER_NAMES`),
  отмечают через @ или отвечают на сообщение бота.
- **Важное — вам**: болезнь, утрата, сообщения с незнакомых номеров и всё, на что
  бот не смог уверенно ответить, пересылаются вам.

## Как это работает

```
WhatsApp ─► POST /webhook ─► проверка подписи ─► парсинг события
   ─► идемпотентность (event id) ─► определение родственника по номеру
   ─► история (краткосрочная память) + подтверждённые факты (долгосрочная)
   ─► режим GREETING_ONLY / FULL_CHAT ─► структурированный контекст
   ─► Claude API ─► validation (+1 повтор с замечаниями)
   ─► WhatsApp API (при ошибке — outbox и повторная отправка) ─► сохранение диалога
```

| Модуль | Что делает |
|---|---|
| `app/main.py` | FastAPI: `/webhook`, `/health`, админ‑API, демо‑интерфейс `/demo` |
| `app/webhook.py` | Пайплайн обработки сообщения (класс `Assistant`), приветствия, outbox |
| `app/claude.py` | Вызов Claude API: timeout/retry, обработка ошибок и refusal, vision для фото; офлайн‑генератор для демо; выбор модели |
| `app/gemini.py` | Бесплатный Google Gemini с тем же интерфейсом |
| `app/bridge.py` + `bridge/index.js` | Бесплатное подключение к WhatsApp как «связанное устройство» (Baileys) |
| `app/commands.py` | Команды владельца из WhatsApp (`/авто`, `/привет`, `/пауза`…) |
| `app/scheduler.py` | Приветствия по расписанию со случайными паузами |
| `app/prompts.py` | System prompt и сборка минимального JSON‑контекста |
| `app/validation.py` | Детерминированная проверка ответа перед отправкой |
| `app/memory.py` | SQLite: родственники, история, факты, кандидаты в факты, события, outbox |
| `app/whatsapp.py` | WhatsApp Cloud API: verification challenge, подпись, парсинг, отправка, скачивание медиа |
| `app/media.py` | Интерфейсы speech‑to‑text / TTS (точки расширения) |
| `app/config.py` | Настройки из переменных окружения / `.env` |

### Режимы

- **FULL_CHAT** — отвечает на конкретное сообщение с учётом истории.
- **GREETING_ONLY** — одно короткое приветствие, отличное от последних
  (они передаются модели в `recent_greetings`). На входящие сообщения в этом
  режиме бот не отвечает, а пересылает их вам. Приветствия отправляет
  планировщик, команда `/привет` или `POST /admin/greet/{relative_id}`.

### Защита от выдуманных фактов

1. System prompt прямо запрещает выдумывать факты; в контекст попадают только
   подтверждённые факты (`known_facts`).
2. `validation.py` ищет в ответе утверждения о пользователе — «расидам»
   (приехал), «ман дар … ҳастам» (я в …), «дар кор ҳастам», «бемор шудам»,
   «пагоҳ меоям», «пул мефиристам» — и отклоняет их, если нет подтверждающего
   факта. Claude получает замечание и пишет новую версию; если и она не прошла,
   ничего не отправляется.
3. Валидатор также блокирует утечки (system prompt, API, JSON, Claude, AI, бот…),
   не‑кириллический текст, слишком длинные ответы и > 3 emoji.

### Память

- **Краткосрочная** — последние `HISTORY_LIMIT` (24) сообщений диалога с
  ограничением по объёму (~6000 символов), отдельно для каждого родственника.
- **Долгосрочная** — таблица `facts`. Факты с одинаковым `key` конкурируют:
  побеждает более надёжный источник (`user` > `config` > `conversation`),
  затем более высокая уверенность.
- **Кандидаты в факты** — из сообщений родственников автоматически
  выделяются важные события (здоровье, свадьба, рождение, учёба, работа,
  поездки, утрата, жильё). В контекст они попадают **только после
  подтверждения** (`POST /admin/fact-candidates/{id}` или кнопка в демо).

### Голос и изображения

- Голосовое → скачивание → `Transcriber` → текст в контекст. По умолчанию
  STT не подключён: Claude получает пометку, что содержание неизвестно, и
  отвечает, не делая вид, что понял. Подключить STT — реализовать
  `Transcriber.transcribe()` в `app/media.py`.
- Фото → скачивание → краткое описание через Claude vision → контекст.
- TTS‑ответы голосом: интерфейс `Synthesizer` уже есть (Phase 3).

### Надёжность

- **Идемпотентность:** каждый `message.id` регистрируется атомарно; повтор
  события не вызывает повторного ответа. Временные сбои Claude помечают
  событие как `retryable` (не более 3 попыток).
- **Claude недоступен:** SDK делает retry с backoff (`LLM_MAX_RETRIES`),
  timeout `LLM_TIMEOUT_SECONDS`; при провале ничего не отправляется.
  Включён серверный fallback при refusal (`LLM_USE_FALLBACKS`).
- **WhatsApp недоступен:** ответ сохраняется в `outbox`, повторная отправка
  раз в 60 секунд (не более `OUTBOX_MAX_ATTEMPTS`) или через
  `POST /admin/outbox/retry`.
- **Логи:** event id, relative id, режим, статус, время обработки, ошибки.
  Секреты не логируются; текст сообщений — только при `LOG_MESSAGE_TEXT=true`.

## Для разработчиков: запуск без WhatsApp и ключей

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # поставьте DRY_RUN=true
uvicorn app.main:app --reload
```

Откройте http://localhost:8000/demo — интерфейс в стиле WhatsApp, где можно
писать от имени любого родственника и видеть ответ, историю, факты и
кандидатов в память. Без `ANTHROPIC_API_KEY` работает простой офлайн‑генератор
на шаблонах (только для демонстрации). Демо никогда не отправляет реальные
сообщения в WhatsApp.

## Подключение Claude

В `.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
LLM_MODEL=claude-opus-5-5
LLM_EFFORT=low
```

`LLM_EFFORT` (`low`/`medium`/`high`) — баланс качества и стоимости; для коротких
семейных сообщений обычно хватает `low`. Если аккаунт не поддерживает
бета‑функцию fallback, поставьте `LLM_USE_FALLBACKS=false`.

> Переменные названы `LLM_*`, а не `CLAUDE_*`, чтобы не конфликтовать с
> переменными окружения самого Claude Code.

## Родственники

Скопируйте `config/relatives.example.json` в `config/relatives.json`
(файл в `.gitignore`) и заполните:

```json
{
  "known_facts": [{"fact": "User works on weekdays", "source": "user", "confidence": 1.0}],
  "relatives": [
    {"id": "mom", "phone": "992900000001", "name": "Модар", "relation": "mother",
     "age_group": "elder", "address": "Модарҷон", "mode": "FULL_CHAT"}
  ]
}
```

- `phone` — в международном формате без `+` (так его присылает WhatsApp).
- `age_group`: `elder` | `peer` | `younger`; для `elder` используется «Шумо».
- `address` — как пользователь обычно обращается к человеку.
- `mode`: `FULL_CHAT` (по умолчанию) или `GREETING_ONLY`.
- Сообщения с неизвестных номеров игнорируются (`IGNORE_UNKNOWN_SENDERS=true`).

## Официальный WhatsApp Cloud API (вместо bridge)

`WHATSAPP_MODE=cloud`. Требует отдельный номер и приложение Meta:

1. Создайте приложение на https://developers.facebook.com → продукт **WhatsApp**.
2. Возьмите **Phone number ID** и постоянный **access token**
   (System User token) → `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_TOKEN`.
3. Придумайте `WHATSAPP_VERIFY_TOKEN`; **App Secret** из настроек приложения →
   `WHATSAPP_APP_SECRET` (проверка подписи `X-Hub-Signature-256`).
4. Опубликуйте сервер по HTTPS (деплой или `ngrok http 8000`) и укажите
   Callback URL `https://<host>/webhook` + verify token; подпишитесь на поле
   `messages`.
5. Установите `DRY_RUN=false` и задайте `ADMIN_TOKEN` (без него в боевом режиме
   админ‑API и демо закрыты).

Ограничение WhatsApp: свободный текст можно отправлять только в течение 24 часов
после последнего сообщения человека. Проактивные приветствия вне этого окна
требуют одобренного шаблона (message template) — WhatsApp вернёт ошибку, и
сообщение останется в outbox.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/webhook` | verification challenge Meta |
| POST | `/webhook` | входящие события WhatsApp |
| GET | `/health` | состояние (Claude API / офлайн, WhatsApp live / dry‑run) |
| GET/POST | `/admin/relatives` | список / добавление родственника |
| GET/POST | `/admin/facts` | факты (долгосрочная память) |
| GET | `/admin/fact-candidates` | кандидаты в факты |
| POST | `/admin/fact-candidates/{id}` | `{"approve": true}` — подтвердить |
| POST | `/admin/greet/{relative_id}` | отправить GREETING_ONLY |
| POST | `/admin/outbox/retry` | повторить неотправленные |
| GET | `/demo` | демо‑интерфейс |

Админ‑эндпоинты требуют заголовок `X-Admin-Token`, если задан `ADMIN_TOKEN`.

```bash

```

Покрыты все сценарии из раздела 28 брифа: приветствие мамы, вопрос старшего,
неизвестный факт, местоположение, планы, хорошая и плохая новость,
GREETING_ONLY, FULL_CHAT, повторный webhook, timeout Claude, ошибка WhatsApp,
пустое и непонятное сообщение, голосовое, изображение — плюс валидация,
память, подпись webhook и формат запроса к Claude API (SDK замокан, реальные
вызовы не делаются).
